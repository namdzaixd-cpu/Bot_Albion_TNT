System architecture

Dữ liệu đi qua những ranh giới rõ ràng

Discord Bot và Dashboard dùng chung Supabase nhưng có runtime độc lập. Browser không cầm service-role key; mọi thao tác quản trị đi qua API server-side và Discord OAuth.

Input

Discord & Officer

Slash command, message, voice state, reaction và forum apply đi vào từng cog chuyên trách.

Runtime chính

Python Discord Bot

Load 9 cog, đồng bộ command theo guild, giữ heartbeat, watchdog và Flask keep-alive.

External

Albion & Bank APIs

Albion GameInfo phục vụ member/guild; UnbelievaBoat xử lý số dư trong Core-Bank.

Data plane

Supabase

Postgres, json_storage, config, transaction history, activity, heartbeat và system logs.

Control plane

Next.js Dashboard

Discord OAuth, API route server-side, quản trị module và quan sát trạng thái hai bot.

Runtime tách riêng

AI Chatbot

Token, deploy và vòng đời riêng; hoạt động trong cùng guild nhưng không còn nằm trong bot chính.

Luồng cấu hình: Dashboard → Supabase → webhook reload → cog xóa cache → lần đọc kế tiếp nhận cấu hình mới.

Data & resilience

Supabase là nguồn dữ liệu production

Bot không còn phụ thuộc vào file JSON local để giữ state vận hành. Thư mục bot/Storage chỉ còn là dấu vết legacy; lớp storage hiện ánh xạ key file sang bảng json_storage và các module quan trọng dùng bảng chuyên biệt.

Lazy client

Khởi tạo an toàn

Client Supabase chỉ được tạo khi cần và trả lỗi rõ khi CI thiếu credential.

3 attempts

Retry có backoff

Database wrapper thử lại tối đa ba lần với khoảng chờ tăng dần.

60 seconds

Heartbeat thật

Bot ghi last_seen và latency mỗi phút để Dashboard phân biệt online/offline.

Config reload

Không cần restart

Dashboard báo bot xóa cache cấu hình; lần đọc sau nhận dữ liệu mới từ Supabase.
